## 2. 식별 시나리오 전체 경로 (재확인)

```
폰 카메라
  ↓
클라이언트 (이미지 raw binary)
  ↓
메인서버 (POST /v1/media/intent → 보관 PC PUT 토큰 발급)
  ↓
보관 PC (이미지 본체 저장 — 10.10.10.122:8004)
  ↓
메인서버 (POST /v1/pill/identify — 이미지 URL 만 전달)
  ↓
이미지 추론서버 (10.10.10.128:8003) ← 인효 담당
  ├─ 보관 PC 에서 URL 로 이미지 GET
  ├─ YOLO 검출 + OCR 각인 + OpenCV 색/모양/크기
  └─ 키값 4종 반환 (각인·색·모양·크기)
  ↓
메인서버 (식약처 낱알식별 캐시 매칭)
  ↓
LLM 서버 (10.10.10.120:8002) ← 윤식·동주 담당
  ├─ DUR + e약은요 RAG
  ├─ 프롬프트 엔진
  └─ 약품 식별 + 자연어 안내
  ↓
클라이언트 결과 화면
```

**핵심 결정**: 메인서버는 **이미지 본체 안 받음** — URL 라우팅만. 이미 구현된 사진 흐름 ⑤+⑥ 설계와 일치 ✅

## 3. LLM + RAG (오늘 신규 진입)

### 3.1 환경 제약
| 항목 | 제약·기준 |
|---|---|
| GPU/VM 메모리 | **24 GB** |
| 언어 | 한국어 필수 |
| 런타임 | **Ollama** 또는 대안 — 오늘 결정 필요 |
| 라이선스 | 상업적 사용 가능 (포트폴리오 → 사업화 대비) |

### 3.2 모델 선정 후보 (회의 중 언급)
- **Gemma** — 동주 일주일 테스트 결과 24GB Max 로 겨우 돌아감
- **대안 Plan B** — 동주 님 이전 프로젝트 프롬프트 개조로 단축

→ 상세 비교는 **[LLM_Model_Candidates.md](LLM_Model_Candidates.md)** 참조.

### 3.3 개발 범위 (윤식)
> "솔직히 우리가 개발할 부분은 프롬프트 빼고는 없어요."
- 모델 학습 ❌
- 모델 환경 설정 ✅
- **프롬프트 엔지니어링** ✅ (핵심)
- RAG 데이터 적재 (DUR + e약은요) ✅
- 아키텍처 설계 ✅

### 3.4 모델 사이즈 판단
> "키 값만 분석하니까 큰 모델 쓸 필요 있을까."
- **Stage A — 추론 결과 키값 4종 → 약품 식별/요약** → 가벼운 모델 (1-3B) 충분 가능
- **Stage B — 사용자 자연어 질문 응답** → 중급 모델 (7-14B) 필요할 수도

## 4. 이미지 추론 서버 현황 (인효)

### 4.1 측정 결과
| 항목 | 값 |
|---|---|
| 모델 | 단일 YOLO (각인·색·모양 미포함) |
| 학습 데이터 | 200장 |
| 학습 시간 | 3-4분 |
| 학습 정확도 (accuracy) | **0.9** |
| 실측 — 4개 알약 검출 | 3·4·5 들쭉날쭉 (false positive/negative) |
| 각인까지 합쳤을 때 신뢰도 | 약 50-60% (애매한 판단) |

### 4.2 원인 추적 (회의 중 발견)
**이미지 ↔ 라벨 데이터 미스매치**
- 라벨링 JSON (bbox 좌표) 은 정상 수신
- 그러나 **3TB 이미지 데이터 중 맨 위 일부만 다운로드**
- 라벨이 가리키는 실제 이미지가 없는 상태로 학습 → 정확도는 학습 셋에서 높게 나오나 실제 추론 실패
- 압축 파일 중 일부만 압축 해제된 상태로 발견

### 4.3 처방
1. PuTTY 로 서버 접속 → 안 풀린 zip 압축 해제
2. AI Hub 데이터 정합성 확인 (라벨 ↔ 이미지 매칭)
3. YOLO 재학습 (`TrainingServer/Scripts/TrainYolo.py`)
4. 정확도 + 개수 판별 재측정
