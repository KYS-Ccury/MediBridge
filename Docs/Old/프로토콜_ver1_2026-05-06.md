# 📡 메디브릿지 (MediBridge) 통신 프로토콜 정의서

## 1. 시스템 통신 아키텍처 개요

본 프로젝트는 4대의 PC(또는 논리적 분리 환경)와 외부 API를 아우르는 통신 구조를 가집니다.

- **GUI PC ↔ 운용 서버 PC**: TCP/IP 기반 통신 (이미지, 음성 전송 및 API 요청).
- **운용 서버 PC ↔ 추론 PC**: HTTP 기반 REST API 통신.
- **운용 서버 PC ↔ 식약처 OpenAPI**: HTTPS (캐시 미스/TTL 만료 시에만 제한적 호출).
- **학습 서버 → 추론 PC**: SCP / 파일 전송 (모델 배포 시에만 통신).

---

## 2. [GUI PC ↔ 운용 서버 PC] 클라이언트 통신 명세

클라이언트(GUI)와 서버 간의 데이터 교환을 담당합니다. 기본적으로 TCP/IP를 사용하며 주요 기능은 REST API 형태로 분리되어 있습니다.

### 2.1 사용자 인증 및 계정 (모듈 6)

- **회원가입**
    - `POST /auth/signup`
    - 요청: 아이디(이메일), 비밀번호, 닉네임
    - DB 매핑: `users` 테이블 생성
- **로그인 및 로그아웃**
    - `POST /auth/login`: 아이디/비밀번호 검증 후 세션 또는 토큰(JWT 등) 발급
    - `POST /auth/logout`: 세션/토큰 무효화

### 2.2 복약 이력 및 보고서 (모듈 2, 5)

- **복약 이력 기록**
    - `POST /history/record`
    - 요청: 복용 시각(년·월·일·시·분), 약 이름, 개수, 메모
    - DB 매핑: `medication_intake_logs` 테이블 저장
- **복약 이력 조회**
    - `GET /history/list`
    - 요청: 일자별, 약별, 기간별 필터 파라미터
- **보고서 생성**
    - `GET /report/generate`
    - 응답: 의사 상담용 통합 보고서 PDF/HTML 반환
    - DB 매핑: `user_reports` 테이블 저장 및 통계 추출

### 2.3 미디어(이미지/음성) 송수신 (TCP/IP)

- 카메라 캡처 이미지(다중 알약 사진) 및 마이크 음성 데이터를 TCP/IP 스트림 또는 페이로드 형태로 운용 서버에 송신.
- 운용 서버는 식별 결과, 신뢰도 분기 정보, 능동/대화형 가이드 텍스트(TTS용)를 GUI PC로 반환.

## 3. [운용 서버 PC ↔ 추론 PC] AI REST API 명세

운용 서버가 AI 추론 모델을 호출하기 위해 추론 PC로 전송하는 내부 REST API 통신 규격입니다.

### 3.1 Vision 영역 (알약 식별)

- **알약 검출 및 Crop (YOLO26)**
    - `POST /vision/detect`
    - 요청: 이미지 바이너리(PNG/JPEG)
    - 응답: `[{ bbox, crop_id, confidence }]`, 상태 코드 (능동 가이드 트리거용)
- **각인 인식 및 색상/모양 분석 (PaddleOCR + OpenCV)**
    - `POST /vision/analyze`
    - 요청: Crop된 알약 이미지
    - 응답: 각인 텍스트, 색상(HSV), 모양 분류 결과, 신뢰도 값

### 3.2 Speech 영역 (음성 인식)

- **음성 텍스트 변환 (Whisper STT)**
    - `POST /speech/stt`
    - 요청: 오디오 바이너리 데이터
    - 응답: 변환된 텍스트 및 인식 신뢰도

### 3.3 LLM 및 Intent(의도 분류) 영역

- **일상 사용 의도 분류 (Stage 0.5)**
    - `POST /intent/classify`
    - 요청: 사용자 발화 텍스트 (±이미지 컨텍스트)
    - 응답: 의도 카테고리 라벨 (약 식별/위험 점검/정보 확인 등), 신뢰도 (반드시 JSON 스키마 형식으로만 반환)
- **등록(Onboarding) 약명 정규화**
    - `POST /onboarding/normalize`
    - 요청: STT로 인식된 약명 텍스트
    - 응답: 정규화된 약명 후보
- **동명/동성분 분기 질문 생성**
    - `POST /onboarding/disambiguate`
    - 요청: 동명 약 후보 리스트
    - 응답: 분기를 위한 사용자 질문 텍스트
- **비위험 정보 일반 안내 (e약은요 RAG)**
    - `POST /summary/non-medical`
    - 요청: 효능, 복용법 등 식약처 비위험 정보 원문
    - 응답: 자연어로 요약된 TTS 출력용 텍스트

## 4. [운용 서버 PC ↔ 외부 / DB] 통신 규약

- **식약처 OpenAPI 연동**: HTTPS 방식으로 통신하며, 운용 중에는 캐시 미스 혹은 TTL(30일) 만료 시에만 외부 호출을 수행하여 장애 영향을 최소화합니다.
- **MariaDB 통신**: 운용 서버는 SQL 인젝션 방어를 위해 반드시 파라미터 바인딩을 사용하여 DB와 통신합니다. 연동 시 `pill_ingredient_mapping`을 통해 특정 약의 성분을 역추적하고 `dur_interaction_cache`에서 병용금기 위험을 점검합니다.
