# 안드로이드 S24 폰 셋업 매뉴얼

| 항목 | 내용 |
| --- | --- |
| **문서 종류** | 안드로이드 S24 폰 입력 디바이스 셋업 매뉴얼 |
| **대상 디바이스** | Samsung Galaxy S24 (Android 14+) |
| **역할** | 카메라 + 마이크 + **온디바이스 STT (Galaxy AI / `SpeechRecognizer`)** + PWA 클라이언트 |
| **버전** | v1.2 |
| **작성일** | 2026-05-06 |
| **작성자** | 팀 (3인) |

> 본 매뉴얼은 메디브릿지의 입력 디바이스로 사용하는 안드로이드 S24의 셋업 절차를 정리한다. **폰에 새로 설치하는 앱은 없으며**, OS에 내장된 기능(개발자 옵션, 무선 디버깅, 삼성 키보드 음성 입력, 시스템 카메라, 브라우저)만 활성화한다.

---

## 1. 셋업 항목 요약

| # | 항목 | 용도 | 설치 여부 |
| --- | --- | --- | --- |
| 1 | **개발자 옵션 활성화** | 무선 디버깅 사용 위해 필요 | OS 내장 (활성화만) |
| 2 | **무선 디버깅 ON** | scrcpy 미러링 + ADB 연결 | OS 내장 |
| 3 | **삼성 키보드 음성 입력 (Galaxy AI STT)** | 음성→텍스트 변환 (온디바이스) | OS 내장, 설정만 확인 |
| 4 | **브라우저 (Chrome 또는 Samsung Internet)** | PWA 페이지 접속 | OS 기본 설치 |
| 5 | **시스템 카메라 앱** | `<input type="file" capture>` 호출 시 자동 사용 | OS 기본 설치 |

> **중요**: 본 프로젝트 MVP에선 **별도 안드로이드 앱(APK) 설치를 하지 않는다.** 모든 기능은 OS 내장 기능 + 브라우저 PWA로 구현.

## 2. 사전 준비

- 안드로이드 S24 (Android 14+)
- 같은 WiFi 라우터에 PC와 폰이 연결 (또는 USB 케이블 직결)
- Samsung 계정 로그인 (Galaxy AI 사용 시 권장)

## 3. 개발자 옵션 활성화

### 3.1 빌드 번호 7번 탭

1. **설정** → **휴대전화 정보** (또는 "전화 정보")
2. **소프트웨어 정보** 진입
3. **"빌드 번호"** 항목을 **연속 7번 탭**
4. "이제 개발자가 되었습니다" 토스트 메시지 표시
5. (PIN/패턴 잠금 사용 중이라면 인증 요청)

### 3.2 개발자 옵션 진입

1. **설정** 메인으로 돌아가기
2. 검색창에 **"개발자 옵션"** 검색 → 진입
3. 또는 **설정 → 휴대전화 정보 → 개발자 옵션** 경로
4. 상단 **"개발자 옵션"** 토글을 **켜기 (ON)**

## 4. ADB 연결 — USB 직결 (권장) vs 무선 디버깅

### 4.0-A 사전 점검 — PC와 폰이 같은 네트워크인가?

무선 디버깅을 쓰려면 **PC와 폰이 반드시 같은 LAN(같은 라우터/공유기)** 에 있어야 한다. 두 디바이스 IP의 앞 3자리(C 클래스) 가 같아야 한다.

```cmd
:: PC 측 IPv4 확인
ipconfig
```

```
:: 폰 측 IPv4 확인
설정 → 연결 → WiFi → 연결된 네트워크 탭 → 상세
```

| PC IP | 폰 IP | 같은 네트워크? | 무선 디버깅 |
| --- | --- | --- | --- |
| `192.168.0.x` | `192.168.0.y` | ✅ Yes | 가능 |
| `10.10.10.x` | `192.168.0.y` | ❌ No (분리됨) | **불가 — USB 직결로 전환** |
| `192.168.1.x` | `192.168.0.y` | ❌ No | **불가 — USB 직결로 전환** |

> 사내·기관 환경에서 PC가 유선 LAN으로 사내망에 붙어있고 폰이 가정/모바일 WiFi 공유기에 붙어있으면 **다른 네트워크인 게 일반적**이다. 이 경우 **4.A USB 직결** 절로 진행.

---

### 4.A USB 직결 (권장 — 다른 네트워크 환경 또는 안정성 우선)

#### 4.A.1 사전 작업 — 보안 위험 자동 차단 해제

(아래 4.0-B와 동일 — 이미 해제했으면 건너뜀)

#### 4.A.2 USB 디버깅 ON

1. 설정 → 개발자 옵션
2. **"USB 디버깅"** 토글 **ON**
3. (선택) "무선 디버깅"은 OFF로 둬도 됨

#### 4.A.3 USB 케이블 연결

1. **데이터 전송 가능한 USB 케이블** 사용 (충전 전용 ❌, S24 박스 동봉 케이블이면 OK)
2. PC USB 포트에 연결
3. 폰 화면 **"USB 사용 옵션"** → **"파일 전송 (MTP)"** 또는 **"PTP"** 선택
4. **"USB 디버깅을 허용하시겠습니까?"** → **"이 컴퓨터에서 항상 허용"** 체크 → **"허용"**

#### 4.A.4 PC에서 인식 확인

```cmd
adb devices
```

→ `<디바이스 시리얼>     device` 표시되면 OK.

#### 4.A.5 PWA 통신용 포트 포워딩 (PoC 단계에서 사용)

```cmd
adb reverse tcp:8000 tcp:8000
```

> **의미**: 폰이 `localhost:8000` 으로 요청 → ADB가 USB 경유하여 PC의 `localhost:8000` 으로 포워딩. 같은 네트워크 필요 없음. 사내 방화벽·네트워크 정책 영향 0. PWA 페이지 접속 시 폰 브라우저에서 `http://localhost:8000` 입력.

---

### 4.B 무선 디버깅 (같은 네트워크 환경에서만)

**전제**: 4.0-A 점검 결과 PC와 폰이 같은 네트워크일 때만 가능.

#### 4.0-B ⚠️ 사전 작업 — 보안 위험 자동 차단(Auto Blocker) 해제

**삼성 갤럭시 S24 (One UI 6.1+)** 는 기본적으로 **"보안 위험 자동 차단"** 이 켜져 있어 **무선 디버깅·USB 디버깅·알 수 없는 출처 앱 설치를 자동 차단**한다. 이걸 먼저 해제해야 무선 디버깅 토글이 켜진다.

1. **설정** → **보안 및 개인 정보 보호** 진입
2. 스크롤해서 **"보안 위험 자동 차단"** 탭 (또는 "추가 보안 설정 → 보안 위험 자동 차단" 경로)
3. 상단 **토글을 OFF**
4. 보안 경고 다이얼로그가 뜨면 **"끄기"** 또는 **"해제"** 확인
5. (검색창에서 "보안 위험 자동 차단" 또는 "Auto Blocker" 검색하면 바로 이동 가능)

> **개발 기간에만 OFF 권장**, 개발 완료 후 다시 ON. 이 기능을 끄지 않으면 무선 디버깅 토글을 켜도 즉시 차단된다.

### 4.1 무선 디버깅 ON

개발자 옵션 메뉴에서:

1. 스크롤해서 **"무선 디버깅"** 항목 찾기
2. 토글 **ON**
3. 확인 다이얼로그 뜨면 **"이 네트워크에서 항상 허용"** 체크 → **"허용"**

### 4.2 페어링 코드 화면

1. **"무선 디버깅"** 항목을 **다시 탭** (토글이 아닌 항목 자체 클릭)
2. 화면 중간 **"페어링 코드로 디바이스 페어링"** 메뉴 진입
3. 화면에 **IP 주소:포트** 와 **6자리 페어링 코드** 가 표시됨
4. **이 화면을 그대로 두기** — PC 측 `adb pair` 명령에서 사용

> 예시 표시:
> ```
> WiFi 페어링 코드
> 123 456
>
> WiFi 페어링용 IP 주소 및 포트
> 192.168.0.42:43251
> ```

### 4.3 PC와 페어링 (PC 측 명령)

PC PowerShell에서:

```powershell
adb pair 192.168.0.42:43251
```

→ `Enter pairing code:` 가 뜨면 폰 화면의 6자리 코드 입력 → Enter

성공 시 메시지: `Successfully paired to ...`

### 4.4 PC ↔ 폰 ADB 연결

페어링 후 **무선 디버깅 메인 화면**으로 돌아가면 **별도의 IP:port** 가 표시됨 (페어링 포트와 다름):

```
IP 주소 및 포트
192.168.0.42:5555
```

PC 측에서:

```powershell
adb connect 192.168.0.42:5555
adb devices
```

→ `device` 표시되면 OK.

⚠️ **`unauthorized` 표시 시**: 폰에 "USB 디버깅 허용?" 다이얼로그가 떴을 것. **"이 컴퓨터에서 항상 허용"** 체크 후 **허용** → 다시 `adb connect` 시도.

## 5. 삼성 키보드 음성 입력 (Galaxy AI STT) 확인

PWA에서 텍스트 입력창 탭 → 삼성 키보드 마이크 버튼 → **온디바이스 STT(Galaxy AI)** 동작 확인.

### 5.1 삼성 키보드 활성화 확인

1. **설정 → 일반 → 키보드 목록 및 기본값**
2. 기본 키보드: **"삼성 키보드"** 선택
3. 키보드 목록에 삼성 키보드가 활성화되어 있는지 확인

### 5.2 음성 입력 옵션 (선택)

1. **설정 → 일반 → 키보드 목록 및 기본값 → 삼성 키보드**
2. 또는 메모장 앱에서 키보드 띄우고 **마이크 버튼 길게 누르기 → 설정 톱니** 진입
3. **"음성 입력"** → "음성 입력 서비스" 또는 "온디바이스 음성 인식" 옵션 확인
4. 가능하면 **"온디바이스 음성 인식"** 활성화 (네트워크 없이 동작, Galaxy AI 활용)

> **확인 방법**: 메모장이나 카카오톡 등에서 텍스트 입력 → 삼성 키보드 마이크 버튼 탭 → 한국어 발화 → 텍스트가 인식되어 입력되면 OK.

### 5.3 PWA에서의 사용 흐름

본 프로젝트 PWA에서:

1. 텍스트 입력창 탭 → 삼성 키보드 표시
2. **마이크 버튼** 탭 → Galaxy AI 음성 인식 시작
3. 사용자 발화 → **텍스트 자동 입력**
4. PWA 페이지의 "보내기" 버튼 → PC FastAPI 서버로 전송

## 6. 브라우저 + PWA 접속

### 6.1 브라우저 선택

S24에 기본 설치된 다음 둘 중 하나를 사용:

- **Chrome** ⭐ 권장 (`getUserMedia` 호환성·디버깅 가장 좋음)
- **Samsung Internet** (삼성 키보드와 통합 잘 됨)

### 6.2 PWA 페이지 접속

PC FastAPI 서버 실행 후, 폰 브라우저에서:

```
http://<PC의 IP>:8000
```

> PC IP 확인은 PC PowerShell에서 `ipconfig` → "이더넷 어댑터" → IPv4 주소 확인.

페이지가 정상 표시되면 OK.

### 6.3 카메라 호출 흐름

PWA의 "촬영" 버튼 탭:

1. HTML `<input type="file" accept="image/*" capture="environment">` 가 트리거됨
2. **시스템 카메라 앱** 자동 실행
3. 사용자가 사진 촬영 → "사용" 버튼
4. 촬영된 사진 파일이 PWA로 자동 반환
5. PWA가 PC FastAPI로 사진을 POST

> **HTTPS 불필요**: `<input capture>` 방식은 평문 HTTP에서도 동작. `getUserMedia`는 HTTPS 필요하므로 본 MVP에선 사용하지 않음.

## 8. 트러블슈팅

| 증상 | 원인 / 해결 |
| --- | --- |
| **무선 디버깅 토글이 "보안위험 자동 차단에서 차단됨" 으로 안 켜짐** | **One UI 6.1+의 "보안 위험 자동 차단(Auto Blocker)" 이 ON 상태. 4.0-B 사전 작업으로 해제 필요. 설정 → 보안 및 개인 정보 보호 → 보안 위험 자동 차단 → 토글 OFF** |
| **`adb pair` 시 `protocol fault (couldn't read status message): No error`** | **PC와 폰이 다른 네트워크. `ipconfig`(PC) vs WiFi 상세(폰) 의 IPv4 앞 3자리 비교 필요. 다른 네트워크면 무선 페어링 불가 → 4.A USB 직결로 전환** |
| `adb pair` 시 "Connection refused" | 폰 페어링 화면이 닫혔거나 IP/포트가 변경됨. 페어링 화면 다시 열고 새 IP/포트로 재시도 |
| `adb devices` 에 `unauthorized` | 폰의 "USB 디버깅 허용" 다이얼로그 미허용. 폰 화면 확인 후 "이 컴퓨터에서 항상 허용" 체크 → 허용 |
| `adb connect` 후 바로 `offline` 표시 | PC와 폰이 다른 네트워크일 가능성. PC `ipconfig`와 폰 WiFi IP 대역 비교 (`192.168.0.x` vs `192.168.1.x` 등) |
| scrcpy 실행 시 검은 화면 | 폰 화면이 잠금 상태. 폰 잠금 해제 후 재시도 |
| PWA 페이지에서 카메라 호출 시 권한 다이얼로그가 안 뜸 | `<input capture>` 방식은 권한 다이얼로그 없음. 정상 동작. 만약 페이지가 안 뜨면 PC 방화벽 8000번 포트 차단 확인 |
| 삼성 키보드 마이크 버튼이 안 보임 | 설정 → 삼성 키보드 → 음성 입력 활성화 확인. 기본 키보드가 삼성 키보드인지 재확인 |
| 음성 인식 시 "네트워크 연결" 메시지 | 온디바이스 음성 인식이 비활성. 설정에서 온디바이스 옵션 활성화 |
