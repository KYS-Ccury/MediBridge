### 1.1 메디브릿지 플랫폼 모듈 구조

| # | 모듈 | 본 프로젝트 (MVP) | 비고 |
| --- | --- | --- | --- |
| **1** | **알약 식별 + 안전 점검** | ✅ 핵심 | YOLO26·PaddleOCR·OpenCV·LLM·식약처 DUR. 사전 등록 약 풀 기반 |
| **2** | **복약 이력 관리** | ✅ 포함 | 복용 시각·약·개수·메모. 일자별·약별 조회 |
| **3** | 증상 / 부작용 기록 | ⚠️ 확장 | 사용자 증상 텍스트·음성 기록 |
| **4** | 헬스케어 데이터 연동 | ⚠️ 확장 | 핸드폰 심박·걸음·수면 (Health Connect / HealthKit) |
| **5** | **통합 보고서** | ✅ 포함 (공통 인프라) | 의사 상담용 인쇄/PDF |
| **6** | **사용자 계정 / 인증** | ✅ 포함 (공통 인프라) | 회원가입·로그인 |

- **음성 → 복약 이력 자동 기록** ("타이레놀 2알 먹었어")
- **음성 → 복약 이력 자연어 조회** ("어제 먹은 약 뭐야?")
- **복약 알림·리마인더, 가족·간병인 공유, 약사·의료진 연계, 자유 대화 컨텍스트**

## 2. 시스템 요구사항

### 2.1 통합 시스템 구성

- **머신비전 통합 시스템**으로 구축
- 다음 요소를 **모두 활용**해야 함:
    - **서버** — **5대 + 폰** 구성으로 확정 진행:
        - GUI PC (클라이언트, **로컬**)
        - 운용 서버 PC (메인서버, **10.10.10.97**)
        - 데이터 보관 PC (사진 전용, **10.10.10.122**)
        - LLM 학습+추론 PC (**10.10.10.120**, 네트워크 분리 가능 설계)
        - Vision 학습+추론 PC (**10.10.10.128**, 네트워크 분리 가능 설계)
        - + 안드로이드 S24 폰 (USB 직결)
        - 상세는 「[시스템_연결구조 v2.1](시스템_연결구조_ver2.md)」 참조
    - **TCP/IP** (REST API on HTTP) — GUI ↔ 운용 서버 / 운용 서버 ↔ 추론 PC
    - **DB** (운용 서버 MariaDB)
    - **GUI 애플리케이션 — Qt6 + C++ + QML**
    - **AI 모델 (트랜스포머·CNN)**
- **개발 ~ 배포** 전 과정 경험

### 2.2 AI / 알고리즘

- **머신비전** (CNN 기반 모델 등)
- **LLM·RAG 활용 영역 제한**:
    - **의료 안내(DUR 위험 안내, 진단성 응답) 영역에는 LLM·RAG 모두 미사용** — 환각 차단
    - **약 정보 등록(Onboarding)** ✅ RAG 허용
    - **일상 사용 의도 분류기 (Stage 0.5)**: 분류만 (응답 생성 X)
    - **비의료 일반 안내 보조** ✅ RAG 허용
    - 외부 인터넷 출처 사용 금지 (식약처 데이터만)
    - **프롬프트 인젝션 방어**: 입력 검증 + JSON 스키마 락 + 영역 분리
    - **표현 톤** — 단정 문구 금지

### 2.3 시스템 안정성·가용성

- 추론 성능 + 메모리·자원 관리 (모니터링·제어)
- 가용성 설계 (현장 가동률 고려)
- 자동 재연결 / 자원 누수 방지 / 로깅·트러블슈팅
- 외부 API 의존 최소화 (식약처 일괄 적재)

### 2.4 하드웨어 / 인터페이스

- **MVP 입력 디바이스**: **안드로이드 S24 폰** — 카메라 + 마이크 + 온디바이스 STT(Galaxy AI / `SpeechRecognizer`). USB 직결 또는 WiFi
- **확장 카메라**: Basler pylon — MVP 정확도 부족 시
- **확장 STT fallback**: 추론 PC Whisper STT
- **아두이노**: 본 프로젝트 미사용 (교수 컨펌 시 재확인)
- **라즈베리파이 / AWS**: 보류

### 2.5 데이터 접근 원칙
**'데이터부터 찾고'** 그에 맞는 모델 선정 (병목은 데이터 확보)

### 2.6 인증·복약이력·보고서 (모듈 2 / 5 / 6)
- **모듈 6 (인증)**: 회원가입·로그인 (bcrypt·JWT·SQL 인젝션 방어)
- **모듈 2 (복약 이력)**: 분 단위 시각·약명·개수·메모 + 식별 신뢰도·DUR 스냅샷 (선택)
- **모듈 5 (통합 보고서)**: 식약처 e약은요 인용 (LLM 자연어 생성 미사용)

> 상세 기능 요구사항은 「[요구사항 분석서 v2](요구사항_분석서_ver2.md)」 참조.

> ⚠️ **5대 + 폰 + 가명화 + 추론 카테고리별 분리** 구조 확정 진행 — 「[시스템_연결구조 v2.1](시스템_연결구조_ver2.md)」 참조.

핵심 요지 (간략, v2.1 확정):
- **GUI PC ↔ 운용 서버 PC** TCP/IP REST (10.10.10.97:8001)
- **운용 서버 PC ↔ LLM 추론 PC** TCP/IP REST (10.10.10.120:8002) — Stage 0.5 / Onboarding RAG / 일반 안내
- **운용 서버 PC ↔ Vision 추론 PC** TCP/IP REST (10.10.10.128:8003) — YOLO·OCR·OpenCV
- **운용 서버 PC ↔ 데이터 보관 PC** 컨트롤 평면 (경로/토큰 발급), 클라/추론 → 데이터 보관 PC 직접 PUT/GET (10.10.10.122) — 사진 전용
- **운용 서버 PC ↔ 식약처 OpenAPI** HTTPS (e약은요 lazy 캐싱 시에만)
- **Vision PC 학습 시점** Data Storage PC → Vision PC 학습 데이터 일괄 PULL
- **학습+추론 동거** (LLM·Vision PC 각각). 모델 가중치 SCP 배포 단계 생략 (네트워크 분리 시 부활)
- **폰 ↔ GUI PC** USB (카메라 + 마이크 + 온디바이스 STT). **음성 원본 폰 외부 비송신** — STT 텍스트만 흐름

## 8. 포트폴리오 어필 포인트

- **실무형 시스템 설계** — 가용성 우선
- **자원 최적화 역량** — 모델·자원 관리
- **통합 엔지니어링** — HW부터 AI 추론·시각화·배포까지
- **신중한 LLM·RAG 적용** — 의료 안내 영역 차단 (법·윤리적 리스크 인식)
- **외부 인터넷 출처 차단 + 프롬프트 인젝션 방어**
- **외부 API 의존 최소화** — 식약처 일괄 적재
- **폰 온디바이스 STT — 대역폭·개인정보 이중 최적화** (Galaxy AI / `SpeechRecognizer`)
- **TTS 어댑터 — 클라 자체 TTS 우선 + 메인 서버 fallback** (Qt6 `QTextToSpeech` + Windows SAPI 한국어 / `ITtsProvider` 인터페이스, 데이터량·품질 트레이드오프 명시)
- **Onboarding RAG round-trip — 의료용어 모르는 사용자 음성 등록 지원** (다회 분기 질문, 토큰·횟수 제한)
- **음성 + 카메라 멀티모달**
- **능동/대화형 가이드 UX**
- **Qt6 + C++ + QML 기능 단위 모듈 분리**
- **MLOps 5대 + 폰 분리** — 메인 / 데이터보관 / LLM(학습+추론) / Vision(학습+추론) / 클라 + 폰. 추론 카테고리별 분리 + 학습+추론 동거(네트워크 분리 가능 설계)
- **플랫폼 모듈 구조 — 6개 모듈, MVP 4 + 확장 2**
- **인증·복약이력·보고서** — End-to-End 사용자 가치

## 9. MVP 범위 vs 확장 범위 (요지) → [시스템 흐름 정리본 v2 §9](시스템%20흐름%20정리본_ver2.md) 참조

> v3 정리: 모듈별 상세 매트릭스는 시스템 흐름 정리본·요구사항 분석서로 일원화. 본 절은 핵심 요지만.

본 프로젝트 MVP = **모듈 1·2·5·6** (모듈 3·4 및 확장 기능은 범위 외).

| 모듈 | 핵심 (MVP) | 명시적 제외 (확장) |
| --- | --- | --- |
| 모듈 1 | 식별·DUR 병용금기·약 풀 CRUD·등록(음성·직접 입력)·능동/대화형 가이드 | 단일 촬영 등록, DUR ②~⑧ 카테고리, 정확도 모니터링 |
| 모듈 2 | 복용 시각·약·개수·메모 (분 단위) | **음성 자동 기록**, **음성 자연어 조회** |
| 모듈 5 | 복약 이력 + 식약처 부작용 인용 (PDF/HTML) | + 증상·헬스케어 통합, 의사·약사용 표준 양식, 전자 전송 |
| 모듈 6 | 회원가입·로그인 (bcrypt·JWT) | 소셜 로그인, 2FA, 비밀번호 재설정 메일 |
| 공통 인프라 | CSV/스마트싱크 일괄 적재 + e약은요 lazy 캐싱 (TTL 없음) | — |
| 하드웨어 | 안드로이드 S24 폰 | + pylon, Ring Light, Arduino 부저/LED |
| PC 구성 | **5대 + 폰** (메인 10.10.10.97 / 데이터보관 10.10.10.122 / LLM 10.10.10.120 / Vision 10.10.10.128 / 클라 로컬 + 폰) | — |

> Arduino 미사용에 따라 §2.4 "아두이노 활용" 요구사항은 교수 컨펌 시 재확인.
